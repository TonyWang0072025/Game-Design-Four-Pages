# Contributing
Beginners and experienced developers are welcome. Report confusing instructions, unsupported assumptions, weak diagrams, or a real case where the workflow failed.

Include a sanitized input excerpt, project stage, expected behavior, actual output, and tool/model/date when available. Do not submit confidential project data, credentials, or unlicensed third-party assets.

Keep SKILL.md focused on execution. Put detailed method notes in references and user guidance in docs. When changing behavior, update affected examples, quality checks, and validation records.
Use the existing evidence statuses. Do not turn proposals into decisions or claim the method proves fun or balance. Submit original or appropriately authorized contributions under MIT.

Before proposing a change, check links, frontmatter, example consistency, and relevant diagrams. Record real behavior tests separately from formatting checks.
